# httpSession Repo Infrastructure & CI/CD — Design

> **Status:** Approved design — pending user review before implementation plan.

**Date:** 2026-08-26
**Scope:** Repository infrastructure (lint, format, hooks), CI/CD workflows, package organization, and documentation for the `httpSession` package.

**Goal:** Establish a complete developer-facing infrastructure for the `httpSession` Bun/TypeScript package — including Biome-driven quality gates, GitHub Actions CI, automated releases via release-please, conventional-commits enforcement, and a clean internal package layout — before resuming the in-flight core implementation (Tasks 4–7).

**Non-goals (deferred):**
- Building/distributing the package to npm (we'll publish v0.1.0+ once Tasks 4–7 land).
- Migrating off Bun or adding Node-only CI matrices beyond smoke checks.
- Setting up Renovate (Dependabot is sufficient at this size).

## 3. Quality Gates

### 3.1 Local (Husky)

**`.husky/pre-commit`:**
1. Resolve staged files.
2. Run `biome check --write --no-errors-on-unmatched <files>` via `lint-staged`.
3. Re-stage formatted files.

**`.husky/commit-msg`:**
1. Run `commitlint --edit "$1"`.

### 3.2 CI (GitHub Actions — `ci.yml`)

Triggered on `push` to `main` and `pull_request` targeting `main`. Single job with the following steps:

| Step | Tool | Purpose |
|---|---|---|
| Checkout | `actions/checkout@v4` | source |
| Setup Bun | `oven-sh/setup-bun@v2` | Bun + lockfile cache |
| Install | `bun install --frozen-lockfile` | reproducible |
| Lint | `bun run lint` (`biome ci .`) | no errors, no warnings |
| Typecheck | `bun run typecheck` (`tsc --noEmit`) | strict TS |
| Test (Vitest) | `bun run test:vitest` | unit/integration |
| Test (Bun) | `bun run test:bun` | runtime compat |

Failures block merge.

### 3.3 Conventional Commits enforcement

- `commitlint` with `@commitlint/config-conventional`.
- Allowed types: `feat`, `fix`, `chore`, `docs`, `refactor`, `test`, `perf`, `build`, `ci`, `style`, `revert`.
- PR title validated by `wagoid/commitlint-github-action@v6` (block merge on invalid).
- Local enforcement via Husky `commit-msg` hook.

### 3.4 Biome configuration

- **`biome.json`** with:
  - `formatter.enabled: true`, 2-space indent, single quotes, semicolons as needed, trailing commas `all`.
  - `linter.enabled: true` with recommended rules + `suspicious`, `correctness`, `performance`, `style` groups.
  - `javascript.formatter.quoteStyle: "single"`, `trailingCommas: "all"`.
  - `files.includes`: `["src", "tests", "*.json", "*.md"]` (we'll test markdown formatting later).
  - `linter.rules.style.useImportType: "warn"` to encourage `import type`.

## 4. Versioning & Release

### 4.1 release-please

**`.github/workflows/release-please.yml`:**
- Trigger: `push` to `main` (after CI green).
- Action: `googleapis/release-please-action@v4`.
- Strategy: `github` (PR-based) — release-please opens a release PR.
- Permissions required: `contents: write`, `pull-requests: write`, `id-token: write` (npm provenance).
- `release-type: node` (correct for our `package.json` shape).
- npm publish happens automatically when the release PR is merged, via the included `npm-publish` config.

### 4.2 Dependabot

**`.github/dependabot.yml`:**
- Package ecosystem: `npm`, weekly on Mondays.
- GitHub Actions ecosystem: `github-actions`, weekly.
- Labels: `dependencies`.
- Grouping: patch and minor updates combined into a single PR each week.

### 4.3 CHANGELOG

`release-please` writes `CHANGELOG.md` automatically from conventional commit messages. Keep-a-changelog format.

## 5. Package Organization

### 5.1 Internal layout

The existing `src/core/` stays. New directories are introduced as Tasks 4–7 land:

| Directory | Purpose | Task |
|---|---|---|
| `src/core/` | State machine, request/completion types, errors | 1–3 ✅ |
| `src/core/errors/` | Domain-grouped errors (`http.ts`, `decode.ts`, `network.ts`, `timeout.ts`, `cancellation.ts`) | 1–3 ✅ → split now |
| `src/transport/` | `HttpTransport` facade + Fetch strategy + XHR fallback interface | 4 |
| `src/decoding/` | Zod-based `decode()` + status policy (`isSuccess`, `expectSuccess`) | 5 |
| `src/client/` | `HttpClient` orchestration: input → transport → decoding → completion | 6 |
| `src/progress/` | `TransferProgress` + progress observers | 7 |
| `src/index.ts` | Public API barrel — only re-exports, no logic | ongoing |

### 5.2 Public API contract

`src/index.ts` exports the **minimum stable surface**:
- `HttpClient` (Task 6) and `HttpRequest` (✅)
- `RequestCompletion<T>`, `HttpResponseMetadata`, `RequestSnapshot`, `TransferProgress`
- Error classes: `HttpError`, `HttpStatusError`, `NetworkError`, `TimeoutError`, `CancelledError`, `DecodeError`, `InvalidRequestError`, `UnsupportedCapabilityError`
- `HTTP_SESSION_VERSION` constant

### 5.3 TypeScript

- `tsconfig.json` (dev): `strict: true`, `noUncheckedIndexedAccess: true`, `moduleResolution: "bundler"`, includes `tests/**`.
- `tsconfig.build.json` (prod): extends dev, **excludes** `tests/**`, `**/*.test.ts`, used by `bun build` for `dist/`.
- `module: "ESNext"`, `target: "ES2022"`, `moduleDetection: "force"`.

### 5.4 `package.json` extensions

```json
{
  "name": "http-session-core",
  "version": "0.1.0",
  "type": "module",
  "sideEffects": false,
  "engines": {
    "node": ">=20",
    "bun": ">=1.1.0"
  },
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js",
      "default": "./dist/index.js"
    }
  },
  "files": ["dist", "README.md", "LICENSE"],
  "scripts": {
    "build": "bun run scripts/build.ts",
    "lint": "biome check .",
    "lint:fix": "biome check --write .",
    "typecheck": "tsc --noEmit",
    "test": "bun run test:vitest && bun run test:bun",
    "test:vitest": "vitest run",
    "test:bun": "bun test tests/bun",
    "test:coverage": "vitest run --coverage",
    "prepare": "husky install",
    "release": "bun run build && bun publish"
  }
}
```

`scripts.build` is intentionally a placeholder for now — a real `scripts/build.ts` (using `bun build` to emit `dist/`) lands in Task 6 once `HttpClient` exists and we have something worth bundling. Until then `bun run build` can `echo "no build target yet"` so the script exists and CI doesn't fail.

## 6. Documentation

### 6.1 `README.md`

Structure (English, the package is for an English-speaking developer audience):
1. Title + tagline
2. Badges: CI, npm version, license, coverage (when available)
3. TL;DR (5 lines explaining what it is and why)
4. Install (`bun add http-session-core` — placeholder until publish)
5. Quick start (5-line code sample)
6. API surface (table of public exports)
7. Architecture diagram (text-based, links to spec)
8. Contributing (link)
9. License (link)

### 6.2 `CONTRIBUTING.md`

- Workflow: fork → branch → worktree → TDD → PR.
- Strict TDD: RED → GREEN → REFACTOR.
- Conventional Commits (link to spec).
- Branch naming: `feature/<slug>`, `fix/<slug>`, `chore/<slug>`, `docs/<slug>`.
- How to run tests locally (`bun install`, `bun run test`).
- How to open a PR (link to template).
- Code of Conduct (link).

### 6.3 `RELEASE.md`

- Conventional commits determine the bump (release-please handles it).
- How to merge the release PR.
- Rollback: cherry-pick the revert commit and tag a patch release.

### 6.4 `SECURITY.md`

- How to report: GitHub Security Advisories (preferred) + email.
- SLA: 48h acknowledgment, 7d target fix.
- Supported versions table (main branch only for now).

### 6.5 `LICENSE`

MIT. The implementation plan will prompt the user for the **copyright holder name and year** before generating this file (do not commit with a placeholder).

### 6.6 `CODE_OF_CONDUCT.md`

Contributor Covenant v2.1.

### 6.7 Issue & PR templates

- **Bug report:** repro steps, expected/actual, environment, severity.
- **Feature request:** problem, proposed solution, alternatives considered.
- **PR template:** linked issue, type of change, breaking change checkbox, test coverage, conventional commit title, checklist.

## 7. Commit History Plan

This design prescribes that this work lands as **one atomic merge** via `feature/repo-infra-and-cicd` branch, with logical commits in this order:

1. `chore(repo): commit pending .atl gitignore entry`
2. `chore(ci): add GitHub Actions CI workflow`
3. `chore(deps): add dev tooling (biome, husky, lint-staged, commitlint)`
4. `chore(lint): add Biome configuration`
5. `chore(hooks): wire Husky pre-commit and commit-msg hooks`
6. `chore(release): add release-please workflow`
7. `chore(deps): add Dependabot configuration`
8. `docs(readme): add package README`
9. `docs(contributing): add CONTRIBUTING, RELEASE, SECURITY, CoC, templates`
10. `chore(license): add MIT LICENSE`
11. `chore(package): extend package.json (engines, exports, scripts)`
12. `chore(tsconfig): add tsconfig.build.json`
13. `refactor(core): split errors module into core/errors/`

Each commit passes `bun run lint && bun run typecheck && bun run test`.

After this lands on `main`, we resume the core workstream on `feature/http-session-core` (or a continuation branch) starting with Task 4.

## 8. Risks

| Risk | Mitigation |
|---|---|
| Biome config fights user preferences later | Document the choice in `CONTRIBUTING.md`; revisit only with team agreement. |
| Husky breaks on Windows | Document Bun-based fallback (`bunx husky install`). Defer Windows support to a follow-up. |
| release-please misinterprets first commits | First release will be 0.1.0 — manually validated before merging the release PR. |
| Dependabot PRs ignored and accumulate | Auto-label + auto-assign (future); for now weekly cadence + reviewer notification is enough. |
| Strict TDD drift after adding tools | Tasks 4–7 retain the strict TDD plan; tooling is enforcement, not replacement. |

---

## 9. Out of Scope

- Multi-runtime CI matrices beyond Node 20 + Bun latest (no Deno, no edge runtimes yet).
- Public benchmark suite (planned post-1.0).
- Visual regression / example app.
- npm organization scope (publishing as `@scope/http-session-core`).
- Localization of `README.md` (English only for now).
